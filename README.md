# Hallelujah Challenge

A Next.js rebuild of [hallelujahchallengelive.com](https://www.hallelujahchallengelive.com),
the site for the Hallelujah Challenge — an hour-long online praise programme
convened by Pastor Nathaniel Bassey, commencing at 11:59 PM WAT.

This is a private work in progress. It is not serving the live site, which is
still on Wix.

## Running it

Node 20.9 or newer (Next 16 requires it; developed on 26).

```bash
npm install
npm run dev
```

Then <http://localhost:3000>.

| Script | What it does |
|---|---|
| `npm run dev` | Dev server on port 3000 |
| `npm run build` | Production build; every route prerenders static |
| `npm start` | Serve the production build |
| `npm run lint` | ESLint |

There is no test suite. Before committing, the bar is `npx tsc --noEmit`,
`npx eslint .` and `npm run build` all clean, plus a look at the affected page
in the browser — several bugs here only ever showed up on screen.

## The one rule that matters

**Nothing on this site says anything the ministry does not say.**

The copy, the photographs, the giving links, the testimonies and the replay
videos all come from what the ministry actually publishes. They are extracted
by script into `content/`, never retyped and never written from imagination.

This is not a style preference. It is here because the rule was broken three
times, and each time it put something false in front of a reader:

- The Give page carried **invented bank account numbers**.
- The Testimonies page carried **twelve invented testimonies** with invented
  names and countries — one of them a real believer's words, cut down and
  reattributed to someone who does not exist.
- The Watch page printed **replay runtimes generated by a hash function**,
  three past editions whose dates were made up, and three streaming platforms
  the ministry has never linked to.

All three are fixed. The habit that caused them is the thing to watch for: a
page looks unfinished, so something plausible gets written to fill it. If you
cannot source it, leave the space empty or take the feature out.

Two traps worth knowing, both of which caused real errors here:

- **The live site hides content in iframes.** Some pages render their real
  content inside a Wix widget served from `filesusr.com`, which is invisible to
  anything that only reads the page markup. The Partnership page was wrongly
  called empty for exactly this reason. Load the page in a browser and read the
  iframe `src`.
- **Never hand-transcribe.** Retyping a verbatim quote or a binary file loses
  to a script every time. An image was once corrupted by transcription here.

## Where the content lives

| Path | What |
|---|---|
| `content/live/*.txt` | Page copy, verbatim from the live site |
| `content/live/testimonies.json` | The ministry's 110 blog testimonies, with source URLs |
| `content/legal/*.txt` | Privacy, terms and cookies, read at build time by `LegalPage` |
| `content/site-content.md` | Inventory of the live site's copy, page by page |
| `content/images.md` | The 21 live-site images, what each is and where it is used |
| `public/assets/site/` | Those images at original resolution, named by Wix media id |

## Layout

```
app/          routes; 12 static pages
components/   one directory per page, plus ui/ primitives and site chrome
  ui/         Section, Card, Reveal, Display, ArrowLink, Marquee
lib/          session clock, motion tokens, WebGL shader
content/      extracted site content (above)
```

Styling is inline `style` objects over CSS custom properties declared in
`app/globals.css`. Light is the default theme; `[data-theme="dark"]`
overrides the tokens, and a small script in `app/layout.tsx` applies a saved
preference before first paint so the page does not flash.

The motion language — easeOutQuint, long durations, blur-to-sharp entrances,
staggered ambient loops — lives in `lib/motion.ts` and the keyframes in
`app/globals.css`. `prefers-reduced-motion` is honoured globally and forces
end states, so nothing is left stuck mid-blur.

## Known gaps

Things that need a decision or information we do not have:

- **The countdown assumes a session every night.** `lib/session.ts` rolls to
  the next 11:59 PM regardless of the calendar, but the sessions run in
  editions with gaps between them, so between editions the site promises a
  broadcast that is not coming. A calendar-aware version was written and
  reverted; the open question is what the page should say when there is no
  next date to show.
- **Only the October 2026 edition is listed** on the Watch page. Its thirteen
  nights are each verified against the ministry's YouTube channel. Earlier
  editions were removed because their dates could not be confirmed.
- **The Payaza giving link** points at a path containing `feb2026`. That
  matches the live site exactly, so it is not a bug here — but it may be stale
  on the ministry's side and is worth raising with them.
- **The store badges** in `public/assets/site/` are screenshots of Google's and
  Apple's official artwork, as are the partner logos. Replace them with the
  official assets before this is public. The App Store listing 404s, so the iOS
  badge is unlinked until the app ships.
- **Five photographs** the design uses are not reachable from any live page.
  They load from the same CDN but the designer sourced them separately;
  `content/images.md` lists which.
